slang/build

slang/build: slang build, a program as one executable that runs without slang installed.

slang build [--dir] [-o out] [--list] [--strip] [file.slang]

The executable is a copy of the slang runtime with the program appended: its modules as bytecode (found by following require from the main file, packages included) and its asset files, signed ad hoc on macOS. Nothing is compiled from C. When the program needs native extensions (slang/web needs uv and llhttp, for instance), the runtime is first linked from slang's static archives (lib/static: libslang.a and the extensions) with cc or zig cc, once per set of extensions. A package's prebuilt extension cannot be linked: such a program is built with --dir, a directory with the executable, its extensions in lib/ and its assets next to it, as they were.

slang.project can say more (paths are relative to the project):

build: {
  main: "app.slang",            // what `slang build` alone builds
                                // (default: main.slang)
  name: "app",                  // the executable (default: the
                                // project's name, else the main file's)
  output: "bin/app",            // where it goes (-o; --dir: dist/<name>)
  modules: {"plugins/a"},       // modules required by a computed name
  assets: {"static", "data/words.txt"},   // files or directories
  compress: true,               // gzip assets where it saves 10% (true:
                                // all but images, video, archives...;
                                // or a list of paths)
  strip: false,                 // drop line information from bytecode
  codesign: "Developer ID Application: ...",   // macOS: sign with
                                // codesign ("-": ad hoc; default: ad
                                // hoc, by slang itself)
  linker: "zig cc",             // default: cc, else zig cc
}

Bundled assets keep their project-relative paths: the program reads them with slang/os as before (relative paths find bundled files first) and app:static serves them, gzipped ones as they are stored.

command

build.main(arguments: {string}) -> int

slang build with its arguments (see the usage above): builds the executable, or with --list prints what would go into it. Errors are reported on stderr (exit code 1); bad arguments print the usage (2).

returns
the exit code
