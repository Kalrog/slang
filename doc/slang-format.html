slang/format

slang/format: the formatter (slang fmt).

Formatting works on the lossless tree of a file (see slang/peg), not on its AST: extension syntax is expanded while parsing, so only the tree still shows what was written. The layout comes from marks in the format layer, set on the parsers of the grammar (format.gaps, format.indent, ...): they say what goes between two tokens, what is a group that is laid out on one line or broken, what is indented. A document printer in the style of Wadler's "prettier printer" then fits the result into 80 columns.

Syntax that extensions add is formatted when the extension marks its parsers like the core does. Unmarked, it keeps its own line structure (verbatim mode): its gaps are what the source has, re-indented to where the syntax now sits. Core syntax inside it (an expression, a block) is formatted either way. A switch statement, as extensions/switch marks it:

local fmt = require("slang/format")
peg.seq(
  fmt.gaps(g:keyword("switch"), null, "none"),
  fmt.gaps(g:token("("), "none", "none"),
  g:rule("expr"),
  fmt.gaps(g:token(")"), "none", "none"),
  g:token("{"),
  fmt.indent(case_block.parser():star(), "hardline"),
  fmt.gaps(g:token("}"), "hardline"),
)

The marks are listed under Marks. Syntax that marks cannot describe gets a layout function of its own (layout, "extension layouts").

format.source checks its own result before returning it: the output has the same tokens as the input (but for dropped ; and trailing commas), the same AST, and the same comments in the same order.

the layer

format.layer

The peg layer the marks live in (a "text" layer: see slang/peg).

format.mark(parser: table, data: Marks) -> table

The other mark functions are shorthands for this one.

returns
parser with the marks data

format.gaps(parser: table, before?: string, after?: string) -> table

parser with the gaps around it; null leaves a side unmarked.

format.group(parser: table) -> table

parser as a group: on one line if it fits, else broken.

format.indent(parser: table, before?: string, after?: string) -> table

parser indented (its breaks and the gap before it), with the gaps around it.

format.drop(parser: table) -> table

parser whose tokens the formatter leaves out (an optional ;).

format.trailing_comma(parser: table) -> table

parser (an optional , at the end of a list) as a comma written only when its group breaks.

format.verbatim(parser: table) -> table

parser whose gaps stay as the source has them, re-indented.

format.formatted(parser: table) -> table

parser whose gaps are formatted again inside verbatim syntax.

format.layout(parser: table, fn: func(api: LayoutApi, node: table): Doc) -> table

parser whose nodes fn lays out: it returns their document (see doc and "extension layouts" below).

format.role(parser: table, name: string) -> table

parser whose nodes a layout function finds as name (LayoutApi.role).

format.uses_marks(parser: table) -> bool

Whether parser (or a parser inside it) carries format marks. Rule references and parts already marked formatted or verbatim are not looked into (they have a layout of their own).

format.extension(parser: table, owner: string) -> table

The parser an extension registered, marked formatted when it uses marks, else verbatim: what the grammar applies to the syntax an extension adds.

owner
the extension's name, kept in the mark (see owner_at)

format.owner_at(tree: table, pos: int) -> string?

The name of the extension whose syntax the lossless tree has at pos, or null for core syntax. Down from the root, an extension's mark names its owner; a formatted mark without one is core syntax again (what the extension was given, or an expression inside it).

documents

format.doc

What an extension's layout function builds its Doc with, besides strings and lists of documents:

line, softline, hardline   a space / nothing / a break when the group
                           around them is flat, a break when it breaks
group(doc)                 on one line if it fits, else broken
indent(doc)                its breaks indented one more level
fill(parts)                content, separator, content, ...: as many
                           contents on a line as fit (the separators
                           are lines)

For example, a list on one line or one item per line:

local d = format.doc
d.group({"[", d.indent({d.softline, a, ",", d.line, b}), d.softline, "]"})

format.print(doc: Doc, width?: int) -> string

Lays a document out in width columns (80 by default), two spaces per indentation level.

formatting

format.source(text: string, path: string, options?: FormatOptions) -> string?

The formatted text, or null for a file of a compile dialect. Raises when the file does not parse, when formatting does not settle, or when the result fails its checks (same tokens, same meaning, same comments). A slang.project is formatted as the table literal it is.

local out = format.source(os.read_file(path), path, {find_project: true})

slang fmt

format.main(arguments: {string}) -> int

slang fmt [--check] [--stdout] paths...: formats .slang files and slang.project files, directories searched. --check lists the files that would change, --stdout prints the results; otherwise files are rewritten.

returns
the exit code

type Marks

type Marks = {before?: string, after?: string, blank?: bool, group?: bool, indent?: bool, hug?: bool, huggable?: bool | string, fill?: bool, hard_body?: bool, drop?: bool, trailing_comma?: bool, verbatim?: bool, formatted?: bool, owner?: string, break_before?: bool, style?: string, layout?: func(api: LayoutApi, node: table): Doc, role?: string}

The format marks of a parser, merged per node (a parser marked twice has both). A gap is "none", "space", "line" (a space or a break), "softline" (nothing or a break), "hardline" or "brace" (nothing before a {, a space before anything else); an unmarked gap is a space if the source had whitespace there, else nothing.

before?: string
the gap before the node's first token
after?: string
the gap after its last token
blank?: bool
a hardline before the node may keep one blank line
group?: bool
the node is laid out on one line if it fits, else broken
indent?: bool
breaks in the node, and the gap before it, are indented
hug?: bool
when a part inside must break, the group's own breaks stay flat
huggable?: bool | string
a group a hugging layout may break: true, "call" or "body"
fill?: bool
a separated list: as many elements on a line as fit
hard_body?: bool
a block that breaks even with one statement (a catch's)
drop?: bool
the node's tokens are left out (a ;)
trailing_comma?: bool
the node is a , when its group breaks, else nothing
verbatim?: bool
gaps in the node are the source's (extension syntax)
formatted?: bool
gaps in the node are formatted again
owner?: string
the extension whose syntax the node is (see owner_at)
break_before?: bool
an infix operator's chain breaks before it, not after
style?: string
an infix operator's chain: "lines", on one line or one per line
layout?: func(api: LayoutApi, node: table): Doc
the node is laid out by an extension's own function
role?: string
a name the layout function finds parts by (LayoutApi.parts)

type Doc

type Doc = string | {Doc} | table

What the printer lays out: a string, a list of documents (concatenated) or a table made by doc's functions.

type LayoutApi

What a layout function is given to look into its node (a node of the lossless tree) with.

LayoutApi:text(n: table) -> string

returns
the source text of a node

LayoutApi:role(n: table) -> string?

returns
the role mark of a node's parser (role)

LayoutApi:parts(n: table) -> {table}

The nodes inside n that have a role or a layout of their own, in order; what is inside those is not looked into.

LayoutApi:format(n: table) -> Doc

The document of n laid out by the formatter: slang code inside the syntax, or a nested node with a layout of its own.

type FormatOptions

type FormatOptions = {find_project?: bool, width?: int, check?: bool}

What source takes.

find_project?: bool
look up the file's project (see compiler.highlight)
width?: int
the columns to fit in; 80 by default
check?: bool
false skips the checks of the result
