slang/ffi

slang/ffi: calling C libraries without writing C. C declarations are read from text (a header, or a few lines) and a library is loaded with them; its functions are then called like slang functions:

local ffi = require("slang/ffi")
local C = ffi.cdef("typedef struct { int quot; int rem; } div_t; div_t div(int, int); int abs(int);")
local libc = ffi.load(null, C)       // null: the program itself (libc)
libc.abs(-3)                         // 3
libc.div(17, 5)                      // {quot: 3, rem: 2}

A header is read as C reads it: the preprocessor runs (#define, #if, function-like macros; #include is skipped), then the declarations are parsed: typedefs, structs, enums, function prototypes (function bodies, as in inline functions, are skipped). Enum values and #define constants become C.constants.

How values cross (see slang/ffi_core for the details): numbers and bools for the arithmetic types; a string for const char *; a table for a struct (fields by name or by position), returned as a table with the fields by name; for a pointer null, a pointer, a string (its bytes), or a table: a list of elements, or one struct, which is copied back after the call when the pointer is not to const (an out parameter). Pointers index like C (p[i], p.field) and assign; ffi.new allocates memory the collector frees.

A wrong declaration crashes the program as it would in C: the FFI calls what it is told is there. Callbacks (C calling slang), unions, bit fields and long double are not supported yet.

declarations

ffi.cdef(text, options)

cdef(text, [options]) -> the declarations of text: {types, functions, constants, order}. options: defines (macros for the preprocessor, like -D), field_name (a function renaming struct fields for slang), defaults (numbers for fields a table leaves out, by struct and field: {Color: {a: 255}}), and into (earlier declarations to add to, so headers can build on each other).

types by name

ffi.type(name, decls)

type(name, decls) -> the ffi_core type of a C type name: "int", "Vector2", "struct foo", "Vector2 *", "float[4]"

ffi.new(t, count, decls)

new(type, [n], [decls]) -> a pointer to n (1 by default) zeroed values, memory the collector frees once nothing points into it; type is an ffi type or a C type name

ffi.sizeof(t, decls)

sizeof(type, [decls]) -> the size of a C type in bytes

ffi.cast(p, t, decls)

cast(pointer, type, [decls]) -> the address as a pointer to type

ffi.string(p, n)

string(pointer, [len]) -> the C string at pointer (or len bytes)

ffi.offset(p, n)

offset(pointer, n) -> the pointer n elements further

ffi.address(p)

address(pointer) -> the address as an int (0 for null)

ffi.value(p)

value(pointer) -> what it points to, copied (a struct as a table)

libraries

ffi.load(name, decls, options)

load(name, decls, [options]) -> the library: its functions by their C names, bound on first use. name is a path, a library name ("raylib": libraylib.dylib in options.paths, slang's native search paths, /opt/homebrew/lib, /usr/local/lib, /usr/lib, then the system's search), or null for the program itself.

ffi.bind(lib, f, name)

bind(library, decl, [name]) -> the function a declaration from cdef (decls.functions.Name) declares, bound to the library (lib.Name does the same); name is what errors call it

ffi.available()

available() -> whether this slang has the FFI
