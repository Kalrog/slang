slang/peg

slang/peg: parser combinators in the style of petitparser.

A parser is a table with a parse_on function:

parser:parse_on(ctx, pos) -> new position, or -1 on failure

On success the parsed value is left in ctx.value. On failure the message and position are recorded in ctx.fail_msg / ctx.fail_pos (the last failure wins, like petitparser's choice), and the farthest failure in ctx.far_*.

A parser can also build the lossless tree of what it parsed: peg.parse_tree(parser, ctx, pos) parses like parse_on and leaves the node of the parser in ctx.tree, a table {p, start, stop, kids} where p is the parser (or walker entry) and kids its children in source order. A node without kids is a leaf and stands for the text it spans. Every character a parse consumes is covered by exactly one leaf, so joining the leaves gives back the input (peg.text). Parsing for a tree is a separate path (see "the lossless tree" below), so a parse without one costs nothing extra; a parser that has no tree path of its own becomes a leaf.

peg.collect(ctx, pos, tree_path)

collect(ctx, pos, tree_path) -> pos | -1, for code that runs inside a parser without a tree path while ctx.collect is set (see weave): parses with tree_path(ctx, pos) and puts the tree in the list

peg.sub(parser, ctx, pos)

sub(parser, ctx, pos) -> pos | -1: parser:parse_on(ctx, pos), for a custom parser that parses others itself. When a tree is being built, their tree becomes part of the custom parser's node (highlighting and formatting see inside it).

peg.run(parser, input, options)

run(parser, input, {tree}) -> {ok: bool, value, position, tree, message, line, column, far_message, far_line, far_column}; tree (the lossless tree, see parse_tree) only with {tree: true}

peg.tag(child, category)

tag(child, category): parses child; its span is highlighted again under category (it wins over the tokens inside), so an extension can colour what a rule produced (an identifier as a function being declared, say) without changing the value (see peg.highlights)

memoization

peg.memoize(p)

memoize(p): makes p remember its results, in place (every grammar sharing the parser sees it)

peg.place_memos(roots, named)

place_memos(roots, named) -> list of {parser, name}: memoizes every parser in named (parser -> name: the rules and the parsers they were modified from) that leads more than one alternative of a choice or dispatch reachable from roots

peg.skip_space(ctx, pos)

skip_space(ctx, pos) -> pos: skips slang whitespace and comments (the skip function of a walker or dispatch when the trivia rule is the default)

peg.dispatch(parsers, skip, message)

dispatch(parsers, skip, message): an ordered choice over parsers that only tries, in order, the alternatives whose first byte (after skip(ctx, pos), when given) can match. When no alternative can match, message (if given) is recorded as the failure. The tables are built now, from the current resolution of every rule reference, so a dispatch belongs to one sealed grammar.

layers

peg.layer(name, base)

layer(name, base) -> a custom layer starting from the built-in layer base ("text", "raw" or "default")

peg.on(parser, layer, f)

on(parser, layer, f) -> a parser that parses like parser and carries the operations f records for layer (f(pipeline) -> pipeline). The parser itself is not changed: a shared parser (a rule reference, say) keeps no operations from one use.

peg.mark(parser, layer, data)

mark(parser, layer, data) -> on(parser, layer, func(v){ return v:mark(data) })

peg.marks(n, layer)

marks(node, layer) -> the data marked on node's parser for layer, in order

peg.evaluate(tree, layer, buffer, options)

evaluate(tree, layer, buffer, {replay}) -> the value of tree in layer: a built-in layer's name or a layer made with peg.layer. buffer is the input the tree was parsed from. The default layer is the value the parse produced, kept in the tree; {replay: true} computes it from the tree instead, running the functions of map and the walker again.
