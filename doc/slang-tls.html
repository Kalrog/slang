slang/tls

slang/tls: TLS on libuv TCP, with the tls native extension (OpenSSL).

local tls = require("slang/tls")
local conn = async.await(tls.connect("example.com", 443))
async.await(async.write(conn, "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n"))

A Connection works like the uv.tcp handle it wraps (read_start(cb), read_stop(), write(data, cb), shutdown(cb), close(cb), getsockname(), getpeername(), nodelay, keepalive, ...), so slang/async's reader, write and close, and slang/http and slang/ws on top of them, use it as they are. Writes made during the handshake wait for it; a failed handshake (a certificate that does not verify, say) reaches them and the reader as the error.

A client verifies the server's certificate against the system's trust store and the host name by default; verify: false turns that off. A server needs a context with server: true, cert and key (see context).

tls.context(options?: ContextOptions) -> Context

A context for many connections: the tls extension's context, with cert_file, key_file and ca_file read into PEM text first.

local ctx = tls.context({server: true, cert_file: "cert.pem",
  key_file: "key.pem", alpn: {"http/1.1"}})

tls.self_signed(names: {string}, days?: int) -> Certificate

A certificate for local development, valid for days (365), with an EC P-256 key.

names
host names or IP addresses; the first is the subject

connections

tls.client(tcp, server_name?: string, context?: Context) -> Connection

A client connection over a connected uv.tcp handle; its handshake starts at once.

server_name
the name to ask for and verify (needed when verifying)
context
a shared default client context when null

tls.server(tcp, context: Context) -> Connection

A server connection over an accepted uv.tcp handle; the handshake runs as the client's bytes arrive.

tls.connect(host: string, port: int, options?: ConnectOptions) -> async.Future

Connects over TCP and completes the handshake: a Future of the Connection. It fails, with the TCP handle closed, when connecting or the handshake fails.

type ContextOptions

type ContextOptions = {server?: bool, cert?: string, key?: string, ca?: string, verify?: bool, alpn?: {string}, min_version?: string, cert_file?: string, key_file?: string, ca_file?: string}

The options of context: the tls extension's context options, or files to read the PEM text from. A verifying client needs the server's certificate valid for the host name; a verifying server asks the client for a certificate.

server?: bool
a server context (false by default)
cert?: string
PEM text of the certificate chain, leaf first; needed by a server
key?: string
PEM text of the certificate's private key; needed by a server
ca?: string
PEM text of the certificates to trust instead of the system's
verify?: bool
check the peer's certificate (a client does by default)
alpn?: {string}
protocol names to offer or accept, by preference
min_version?: string
"1.2" (the default) or "1.3"
cert_file?: string
a file to read cert from
key_file?: string
a file to read key from
ca_file?: string
a file to read ca from

type Connection

A TLS connection over a uv.tcp handle; type(conn) is "TlsConnection". It also has the handle's getsockname, getpeername, nodelay, keepalive, is_closing, is_active, fileno, ref, unref and has_ref, which go to the TCP handle.

Connection:handshake() -> async.Future

A Future of the connection once the handshake is done (at once when it is); it fails with the handshake's error.

Connection:info() -> Info

The protocol version, cipher, ALPN protocol, peer and server name.

Connection:read_start(cb: func(err: any, chunk: string?))

Calls cb with each chunk of plaintext as it arrives, and with a null chunk at the end of the stream; cb(err, null) when the connection fails.

Connection:read_stop()

Stops calling the reader; plaintext that arrives meanwhile is kept for the next one.

Connection:write(data: string, cb?: func(err: any))

Encrypts and sends data; cb(err) once it is written. Writes made during the handshake are sent after it.

Connection:shutdown(cb?: func(err: any))

Sends a close_notify, then closes the TCP write side.

Connection:close(cb?: function)

Closes the TCP handle; waiting writes and handshakes fail with "tls: the connection is closed".
