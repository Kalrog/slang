slang/compiler

slang/compiler: the compiler driver. It parses slang with the grammar extensions in effect, compiles it to functions, and finds a program's project and packages. It defines the global compile. Tools (the language server, slang fmt, slang doc) use it to see a file as the compiler sees it.

local compiler = require("slang/compiler")
local f = compiler.compile("return 1 + 2", "sum")
f()   // 3
local h = compiler.highlight(source, "main.slang", {symbols: true})

Grammars are scoped: a file's extension statements end with the file. The root grammar is slang plus the ambient layer of the project file (slang.project: extensions loaded into every file, dialects selected by file suffix, search paths; see Project); extension global in the main file and changes made at run time also go to the root. A package's files compile under the package's own slang.project instead. Extensions get the grammar they extend with grammar.

compiler.explain

Whether the compiler tells on stderr what it does: the project and its extensions, the extensions and rule changes of each unit, the packages. slang run --explain sets it; SLANG_EXPLAIN=1 does the same. It also turns on grammar warnings.

compiler.load_extension(name: string)

Runs the extension module name for the grammar being extended (see grammar), once per grammar: a second load does nothing. A module file on the search paths is compiled with load_file and run anew for each grammar that loads it; anything else (an embedded or native module) is required, so it runs once per program.

compiler.grammar() -> table

The grammar of the unit being parsed, or the root grammar at run time (see slang/grammar for what it offers).

returns
the grammar an extension extends

compiler.reset()

Starts over: a fresh root grammar, no project, no packages, the default search paths. Raises while a file is being parsed, unless called from an extension statement. Tools that look at many files (slang fmt, slang doc) reset before each, so one file's project never reaches the next.

compiler.parse(source: string, origin?: string) -> table

Parses with the grammar of the unit that calls it (the root grammar at run time); extension syntax comes out expanded to core nodes.

origin
the name in error messages and locations; "string" by default
returns
the AST

compiler.parse_plain(source: string, origin?: string) -> table

Parses source as plain slang, without the project's extensions (what slang's own library modules are written in).

returns
the AST

compiler.generate(node: table, origin?: string) -> codegen.Prototype

Compiles an AST; vm.load_proto turns the result into a function.

compiler.compile(code: string | table, origin?: string, env?: table) -> function

Compiles source text or an AST table. Source text is parsed with the grammar of the unit that calls compile (an unquote sees the extensions of its file). Raises on a syntax error. This is the global compile.

With env the function's globals are env, not the program's: a sandbox sees only what env holds, and its global assignments stay in env (env.meta = {__index: ...} reads through to other globals). The source then may not run code while it is compiled: unquotes and extension statements are errors, since they would run with the compiler's globals. There are no CPU or memory limits.

local f = compile("return x * 2", "calc", {x: 21})
f()   // 42

project file

compiler.find_project(dir: string) -> string?

The path of slang.project in dir or the nearest directory above it, or null. A relative dir is taken from the working directory.

compiler.dirname(path: string) -> string

The directory part of a path: "." when there is none, "/" for a file at the root.

compiler.join_path(dir: string, path: string) -> string

path relative to dir; an absolute path is returned as it is.

packages

compiler.package_root() -> string

$SLANG_PKG_DIR, else ~/.slang/pkg; a package is <root>/<name>@<version>.

returns
where fetched packages live

compiler.package_dir(name: string, version: string) -> string

The directory of a fetched package's version under package_root.

version
as "1.2.3"

compiler.read_table_file(path: string) -> table

Reads a file that is a slang table literal (slang.project, slang.lock). Raises when it is not one. It is compiled like any slang, so extensions in effect apply.

compiler.packages() -> {[string]: Package}

The program's packages by name: those of the loaded project's slang.lock, its dependencies that are not locked yet (missing), and the project itself when it has a name. Empty without a project. The tables are copies.

compiler.load_project(path: string) -> Project

Reads a project file and applies it: its packages (from slang.lock), search paths (the project's directory first, then its search_paths, then the defaults), dialects and the ambient extensions, loaded into the root grammar. Raises when a project is already loaded or the file is not a table literal.

compiler.absolute_path(path: string) -> string

path from the root, without . and .. parts; a relative path is taken from the working directory. Symbolic links are not resolved.

compiler.stub_path(name: string) -> string?

The stub of a module without slang source (a native one, or "globals" for the global functions): a slang file that declares and documents it, never run; null when there is none. A package keeps the stubs of its modules in its stubs/ ("name/a" is <package>/stubs/a.slang, "name" stubs/init.slang): for native modules, and for modules whose fields are made at run time (a binding through slang/ffi), which tools then read instead of the source.

compiler.module_path(name: string) -> string?

The absolute path of the source file require(name) would load, its stub when it has no source or is a package module with a stub (see stub_path), or null. Sources are looked for on the search paths (the project's first), then among slang's own library modules (slang/http is http.slang in a librarySources directory).

compiler.project() -> Project?

returns
the program's project in effect, or null

compiler.keywords(path: string) -> {string}

The words the grammar of a file at path reserves (its project's and dialect's extensions included), sorted. For a compile dialect, the root grammar's.

bytecode cache

compiler.cache_root() -> string?

$SLANG_CACHE_DIR, else ~/.cache/slang; null when neither that nor HOME is set.

returns
where slang caches what it builds

compiler.load_file(path: string, origin?: string) -> function

Compiles a file as require and slang run do, through the bytecode cache. A file is compiled under its project's grammar (a package's for a file of a package) or that of its dialect, never the grammar of the file that loads it: a module means the same wherever it is loaded from. A file of a compile dialect is handed to the dialect's compile function.

origin
the name in error messages and locations; path by default

compiler.load_main(path: string) -> function

Loads the main file of a program like load_file. The project file is looked up from the file's directory upwards the first time, and the file may use extension global.

highlighting

compiler.highlight(source: string, path: string, options?: ParseOptions) -> Highlight

The tokens of source as the compiler would parse the file at path (its project, its dialect), and its parse errors. Extension code runs as it would in the compiler; nothing is compiled or cached. A file of a dialect with a compile function has no tokens. The tokens are read off the lossless tree (peg.highlights); a statement that fails to parse is reported and highlighted by its words, and the parse goes on after it. A slang.project gets no symbols.

compiler.compile_file(path: string, origin?: string) -> function

Compiles a file as slang run would (its project, its dialect), without the bytecode cache; what slang compile and slang disasm use. Looks the file's project up while none is loaded.

compiler.analyze_file(path: string, origin?: string, main?: bool) -> Analysis

Compiles a file like compile_file and tells the modules it requires, as the code is after its extensions ran. What slang build follows.

main
the file is a program's main file (it may use extension global)

compiler.extension_grammar(name: string) -> ExtensionGrammar

Loads the extension name (as extension "name" would) into a grammar derived from the root, which stays as it is: comparing the two shows what the extension adds (slang doc's extension pages).

compiler.expand(source: string, path: string, options?: ParseOptions) -> string

The file as slang source after its extensions have been applied: parsed like load_file would, then printed from the core AST (unquotes are executed, extension statements are gone, constants folded). A file of a compile dialect is returned as it is. Raises when it does not parse.

compiler.tree(source: string, path: string, options?: ParseOptions) -> table?

The lossless tree of source as the compiler parses the file at path (its project, its dialect; see slang/peg: joining its leaves gives source back), or null for a file of a compile dialect. Extension code runs as it would in the compiler. The tree's ast field is the file's AST. Raises when it does not parse. What the formatter works on.

compiler.expand_file(path: string) -> string

expand for a file, looking up its project (slang expand).

compiler.highlight_file(path: string) -> Highlight

highlight for a file, without symbols, looking up its project the first time like load_main does.

compiler.highlight_json(path: string, check?: bool) -> string

highlight_file as JSON text, {tokens, diagnostics} (slang highlight); the tokens without stop. (slang highlight --check): compile errors, and locals never used and globals not defined as hints and warnings with a length

check
when the file parses, also compile it and lint it on its own

compiler.compile_repl(source: string) -> function

Compiles a line of the REPL with the root grammar: a chunk, or else an expression, whose function returns its value. Extension statements are not scoped: they stay in effect for the lines after.

type Project

type Project = {path: string, dir: string, source: string, extensions: {string}, dialects: {[string]: Dialect}, warnings?: bool | {[string]: bool}, key: string, grammar: table, dialect_grammars: {[string]: table}, package?: string}

A project file as the compiler applies it: the program's (from load_project) or a package's.

path: string
the project file
dir: string
the directory that holds it
source: string
the file's text
extensions: {string}
the ambient extensions, loaded into every file in order
dialects: {[string]: Dialect}
by file suffix (".json")
warnings?: bool | {[string]: bool}
false turns grammar warnings off, a table per extension
key: string
the project file and its extensions' sources, for cache keys
grammar: table
the grammar files of the project compile with
dialect_grammars: {[string]: table}
the grammars made so far for dialects, by suffix
package?: string
the package's name, for a package's project
