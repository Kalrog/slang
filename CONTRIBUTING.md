# Working on slang

How slang itself is built, tested and changed. For using slang, start with
the [README](README.md) and the guides in `website/guide`.

## Building

```sh
make build      # bin/slang (ReleaseFast) and lib/ (the native extensions)
make test       # the slang suite, the native extension tests and the Zig unit tests
make test-safe  # the suites on the checked build and under GC stress
make bench      # bench/
```

Requirements: Zig 0.17 (`brew install anyzig` picks the version pinned in
`zig/build.zig.zon`); libffi (part of macOS, `libffi-dev` on Linux);
libuv, SQLite, OpenSSL 3 and zlib for the native extensions, each with a
`-D<name>=false` option to leave it out and a `-D<name>-prefix` option for
where it is installed (see `zig/build.zig`). raylib and Box2D for their
packages and the examples on them (`brew install raylib box2d`).

`make test-safe` builds into `zig/zig-out-safe` and `zig/zig-out-stress`.
The Makefile's header lists the targets of the packages and the examples.

## Self-hosting

`slang/compiler/*.slang` is the compiler, `slang/lib/*.slang` the slang
part of the standard library. Both are compiled by the interpreter itself
into the seed bytecode in `boot/slang`, which the binary embeds:

```sh
make seed       # recompiles slang/ into boot/slang and rebuilds the binary
make fixpoint   # checks that the seed reproduces itself byte for byte
make test
```

After changing the compiler, run `make seed` twice (the first seed is
compiled by the old compiler, the second by the new one) and then `make
fixpoint`.

A new module in `slang/lib` also goes into the list of names in
`zig/build.zig`, or the seed lacks it.

The compiler ships the root grammar compiled to slang (`slang/pegc`):
`make seed` writes it with `slang/seed_parsers.slang`, and `make fixpoint`
checks it.

## Debugging

- `SLANG_TRACE=1` prints every instruction to stderr.
- `SLANG_GRAMMAR_WARNINGS=1` reports grammar conflicts.
- `slang run --profile out.folded file` (or `SLANG_PROFILE=out.folded`
  with any command) writes a sampled profile as folded stacks.
- `SLANG_PEGC_DEBUG=1` reports which grammars are compiled and why one was
  not; `SLANG_PEGC=0` runs the combinators only.
- On macOS, `sample <pid>` on a longer-running copy of a benchmark is a
  usable profiler of the VM.

## Native extensions

`extensions/native` holds the native modules that come with slang (`uv`,
`sqlite`, `crypto`, `tls`, `llhttp`, `zlib`, `webview`) and two to learn
from (`hello.c`, `vec.zig`). `zig build` compiles each into `lib/`, and as
a static archive into `lib/static` for `slang build`. llhttp is vendored
in `extensions/native/vendor`.

## Documentation

- The guides are Markdown files in `website/guide`. The website renders
  them, and checks that every `slang` sample in them parses.
- The library's reference is made from doc comments (`slang doc`). Native
  code is documented by stubs in `slang/stubs`. `make doc` regenerates
  `doc/`.
- The tour is `website/tour/*.slang`: a page is a program whose leading
  comment is its title and text.

## The website

`website/` is slang's site, generated by slang (`website/build.slang`):

```sh
make wasm       # the VM as WebAssembly, for the playground and for notebooks that run in the page
make website    # the static site in website/out
make serve      # builds it and serves it at http://127.0.0.1:8080 (PORT=...)
```

`make wasm-gfx` builds a second VM for the playground with Emscripten
(`brew install emscripten`, cmake, ninja), with raylib's web platform,
Box2D, Jolt Physics, WebGPU (Emscripten's port of Dawn's `webgpu.h`), SDL3
and libffi's Emscripten port linked in, so that programs on the raylib,
box2d, jolt, gpu and window packages run in the browser
unchanged. `website/web/build.sh` fetches pinned sources. In the browser a
program runs as a coroutine that hands the page control at every frame, so
no ASYNCIFY is needed.

The playground runs `slang run`, `slang fmt` and `slang highlight --check`
in a web worker. Any static file server can serve `website/out`.

## Editors

`lsp/` is the language server. `make vscode` packages the VS Code
extension in `editors/vscode` with it (`make vscode-grammar` regenerates
its TextMate grammar from the core grammar's keywords). `editors/nvim` is
the Neovim plugin.

## Repository layout

| folder | holds |
|---|---|
| `zig/` | the VM (`zig/src/vm`), the native library functions (`zig/src/stdlib`), the CLI, `slang.h` |
| `slang/` | the compiler (`slang/compiler`), the library written in slang (`slang/lib`), the stubs |
| `boot/` | the seed bytecode: `slang/` compiled by itself, embedded by the binary |
| `test/` | the test suite (`slang test`) |
| `bench/` | benchmarks |
| `extensions/` | grammar extensions written in slang; `extensions/native` the native modules |
| `packages/` | packages kept with slang: raylib, box2d, jolt, window, gpu, kernel, dsp, midi, microphone |
| `examples/` | example programs |
| `lsp/`, `editors/` | the language server and its editor plugins |
| `website/` | the site: generator, pages, tour, guides, playground |
| `doc/` | the generated reference of the library |

The earlier implementations, the Go VM (the reference during the Zig
port) and the original Dart one, are on the branch `legacy`.
