slang/compiler

slang/compiler: the compiler driver. Defines the global compile; extensions get the grammar they extend with require("slang/compiler").grammar().

Grammars are scoped: a file's extension statements end with the file. The root grammar is slang plus the ambient layer of the project file (slang.project: extensions loaded into every file, dialects selected by file suffix, search paths); extension global in the main file and changes made at run time also go to the root.

compiler.explain

slang run --explain sets compiler.explain; SLANG_EXPLAIN=1 does the same

compiler.load_extension(name)

load_extension(name): runs the extension module name for the grammar being extended. A module file on the search paths is compiled under the root grammar and run once per grammar that loads it; anything else (an embedded or native module) is required.

compiler.grammar()

grammar() -> the grammar an extension extends: the grammar of the unit being parsed, or the root grammar at run time

compiler.reset()

reset(): a fresh root grammar, no project

compiler.parse(source, origin)

parse(source, origin) -> AST

compiler.generate(node, origin)

generate(node, origin) -> prototype table

compiler.compile(code, origin, trace)

compile(code, origin) -> function; code is source text or an AST table. Source text is parsed with the grammar of the unit that calls compile (an unquote sees the extensions of its file).

project file

compiler.load_project(path)

load_project(path): reads a project file and applies it: search paths, dialects and the ambient extensions (loaded into the root grammar)

compiler.absolute_path(path)

absolute_path(path) -> path from the root, without . and .. parts

compiler.stub_path(name)

stub_path(name) -> the stub of a module without slang source (a native one, or "globals" for the global functions): a slang file that declares and documents it, never run; null when there is none

compiler.module_path(name)

module_path(name) -> the absolute path of the source file require(name) would load, its stub when it has no source (see stub_path), or null: on the search paths (the project's first), else one of slang's own library modules (slang/http is http.slang in a librarySources directory)

compiler.project()

project() -> the project in effect, or null

bytecode cache

compiler.load_file(path, origin)

load_file(path, origin) -> function. A file is always compiled under the root grammar (or the grammar of its dialect): a module means the same wherever it is loaded from.

compiler.load_main(path)

load_main(path) -> function: loads the main file of a program. The project file is looked up from the file's directory upwards the first time, and the file may use extension global.

highlighting

compiler.highlight(source, path, options)

highlight(source, path, {find_project, symbols}) -> {tokens, diagnostics, symbols}: the tokens of source as the compiler would parse the file at path (its project, its dialect), with categories and 1-based line/column, and the parse errors as {line, column, message, severity}. Extension code runs as it would in the compiler; nothing is compiled or cached. A file of a dialect with a compile function has no tokens. The tokens are read off the lossless tree (peg.highlights); a statement that fails to parse is reported and highlighted by its words, and the parse goes on after it. With symbols, the same parse also gives the file's definitions and uses (see slang/symbols; not for a project file).

compiler.compile_file(path, origin)

compile_file(path, origin) -> function: compiles a file as slang run would (its project, its dialect), without the bytecode cache; what slang compile and slang disasm use

compiler.expand(source, path, options)

expand(source, path) -> slang source: the file after its extensions have been applied (parsed like load_file would, then printed from the core AST; unquotes are executed, extension statements are gone, constants folded). A file of a compile dialect is returned as is.

compiler.tree(source, path, options)

tree(source, path, {find_project}) -> the lossless tree of source as the compiler parses the file at path (its project, its dialect; see slang/peg: joining its leaves gives source back), or null for a file of a compile dialect. Extension code runs as it would in the compiler. tree.ast is the file's AST.

compiler.expand_file(path)

expand_file(path) -> expand(...) for a file, with its project

compiler.highlight_file(path)

highlight_file(path) -> the same for a file, looking up its project like load_main does

compiler.highlight_json(path)

highlight_json(path) -> highlight_file(path) as JSON text (slang highlight)

compiler.compile_repl(source)

compile_repl(source) -> function returning the value of an expression or null
