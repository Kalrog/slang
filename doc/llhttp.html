llhttp

llhttp: the native binding of llhttp, the HTTP/1 parser of Node.js. slang/http parses requests and responses with it; most code should use slang/http.

local llhttp = require("llhttp")
local p = llhttp.parser("request", {max_head: 65536})
local events = p:execute("GET /hi HTTP/1.1\r\nHost: x\r\n\r\n")
events[0].url      // "/hi"
events[1].type     // "done"

Parser.execute feeds bytes and returns the list of Events they completed, in order: a "head", then "body" pieces, then "done" for each message; "upgrade" when the connection switches protocol, "error" when the input is not HTTP.

llhttp.version() -> string

The llhttp version as "major.minor.patch".

type Event

type Event = {type: string, method?: string, url?: string, status?: int, reason?: string, version?: string, headers?: {[string]: string | {string}}, keep_alive?: bool, upgrade?: bool, chunked?: bool, content_length?: int, data?: string, rest?: string, code?: string}

What a Parser reports; which fields are set depends on type.

type: string
"head", "body", "done", "upgrade" or "error"
method?: string
head of a request: the method, "GET"
url?: string
head of a request: the request target
status?: int
head of a response: its status code; error: 431 for a head over max_head, else 400
reason?: string
head of a response: its reason phrase; error: what is wrong
version?: string
head: "1.1" and the like
headers?: {[string]: string | {string}}
head: by lowercased name; a repeated header is joined with ", " (cookie with "; "), except set-cookie, which is always a list
keep_alive?: bool
head and done: whether the connection may carry another message
upgrade?: bool
head: whether the message asks to switch protocol
chunked?: bool
head: whether the body is chunked
content_length?: int
head: the Content-Length, when there is one
data?: string
body: a piece of the body, de-chunked
rest?: string
upgrade: the bytes after the head, which belong to the new protocol
code?: string
error: llhttp's error name, like "HPE_INVALID_METHOD"

type ParserOptions

type ParserOptions = {max_head?: int}

How a Parser limits its input.

max_head?: int
the most bytes a head may have; 0 (the default) means no limit

type Parser

A parser of one connection's messages; type() of it is "llhttp.parser".

Parser:execute(data: string) -> {Event}

Feeds data and returns the events it completed. After an "error" event the parser stays failed, and after "upgrade" it is done: execute then returns an empty list.

Parser:finish() -> {Event}

The events that ending the input gives (a response that runs to the end of the connection completes).

Parser:skip_body()

Makes the next head have no body (the answer to a HEAD request).

Parser:reset()

Readies the parser for a new connection.
